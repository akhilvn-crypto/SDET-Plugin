# Issue Logs — traceability

Generated by the SDET pipeline at the end of every `/sdet` and `/runtest` run
(`sdet.js issuelog write`). **Do not edit these files by hand** - they are rebuilt from
`.sdet/state.json`, the test-case files and the bug registry each time.

| File | What it answers |
|---|---|
| `TRACEABILITY.md` | The master matrix: Story → Spec → Test Case → Automation → Last Result → Bug (local and Jira). |
| `<SPEC_OR_STORY_ID>.md` | One story/spec: its summary, the spec versions processed, every test case with its automation and result, the bugs raised, and the run history. |
| `traceability.json` | The same data for tools and dashboards. It also keeps the run history, so keep it under version control. |

Columns you will see:

- **Story**: the Jira user story (when Jira is on), linked to Jira.
- **Spec (ver)**: the specification id and the version that was last processed.
- **Test Case**: `<SPEC_ID>-TCnn`, with its title.
- **Automation**: the Playwright file and test that carry the test case's tag.
- **Last Result**: Pass / Fail / Blocked / Flaky / Not Run from the latest execution.
- **Local Bug**: `bugs/BUG-NNN.md`.
- **Jira Bug**: the Jira key, with how it is linked to the story (Blocks / Relates).
- **Bug Status**: the status recorded in the bug file.
